## What you need

- **macOS or Linux**, running bash or zsh. Windows and PowerShell are not supported yet.
- **Homebrew**, or **Go** if you would rather build the binary yourself.
- **Either an `ANTHROPIC_API_KEY`**, which the default `provider: anthropic`
  uses, **or a logged-in `claude` or `codex` CLI**, which uses your Claude or
  ChatGPT subscription and needs no API key. OpenAI and compatible APIs are
  covered in [Providers](/docs/providers/).

## Install

```bash
brew install rizwanreza/tap/smartly
```

The macOS binaries are signed with an Apple Developer ID and notarized, so
Gatekeeper lets them run with no extra steps.

Or build it yourself with Go:

```bash
go install github.com/rizwanreza/smartly-cli/cmd/smartly@latest
```

That puts a binary named `smartly` in your Go bin directory. If the command is
not found afterwards, that directory is not on your `PATH`:

<Platform>
  <Fragment slot="macos">
```bash
export PATH="$PATH:$(go env GOPATH)/bin"   # add to ~/.zshrc
```
  </Fragment>
  <Fragment slot="linux">
```bash
export PATH="$PATH:$(go env GOPATH)/bin"   # add to ~/.bashrc
```
  </Fragment>
</Platform>

Prebuilt binaries for macOS and Linux are also on the
[releases page](https://github.com/rizwanreza/smartly-cli/releases).

## Connect a model

Pick one. Either way, nothing else is required.

### With an API key

Out of the box smartly needs only this. No config file is required.

<Platform>
  <Fragment slot="macos">
```bash
export ANTHROPIC_API_KEY="sk-ant-..."   # add to ~/.zshrc
```
  </Fragment>
  <Fragment slot="linux">
```bash
export ANTHROPIC_API_KEY="sk-ant-..."   # add to ~/.bashrc
```
  </Fragment>
</Platform>

### With your Claude or ChatGPT subscription

No API key needed. If you're logged into Claude Code or Codex, including on a
seat your company provides, smartly shells out to that session. Log in first if
you haven't:

```bash
claude login    # or: codex login
```

Then run `smartly config init` and set the provider in the `config.yaml` it
writes:

```yaml
provider: claude-cli     # or codex-cli

providers:
  claude-cli:
    model: haiku         # required for claude-cli
```

Or skip the config and pass it for one call with
`--provider claude-cli --model haiku`. `smartly onboard` walks through the same
choice. Each request spawns a CLI process, so it is slower than an API key;
the full tradeoffs are in [Providers](/docs/providers/#cli-backed-providers).

## Your first command

<Callout type="warn" title="This runs the command. Immediately.">
  `execution.mode` defaults to `auto`: smartly generates one shell command and
  runs it with no confirmation prompt, including when the command is
  destructive. Add `--dry-run` to your first few requests until you have a feel
  for what it produces.
</Callout>

Start with `--dry-run`, which prints the command and does nothing else:

<Transform
  invocation="smartly --dry-run"
  request="show hidden files sorted by size"
  command="ls -lahS"
/>

Drop the flag when you want it to run:

```bash
smartly show hidden files sorted by size
```

## Put a gate in front of it

Switch execution mode once and forget about it:

```bash
smartly config init                              # writes a default config.yaml
```

Then set `execution.mode` in that file. Two gates to choose between:

```yaml
execution:
  mode: confirm              # ask before every command
```

```yaml
execution:
  mode: confirm-destructive  # ask on anything it doesn't recognise as safe
```

`confirm` prints every command and waits for `[y/N]`. `confirm-destructive` is
the middle path: a local classifier reads the generated command and lets
recognised-safe ones through, asking on everything else — destructive or
unrecognised alike. It is a best-effort seatbelt, not a sandbox, so if you want
to see every command, pick `confirm`.

You can also force the prompt for a single call with `--confirm`, without
changing any config. All of it is covered in [Execution and
safety](/docs/execution-and-safety/).
